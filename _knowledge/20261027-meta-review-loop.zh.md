# 人在系统之上：每周治理报告与元评审工作法

![深夜书房里，一人坐在大屏前查看自动流水线周报，箭头指向写有「改进机器」的扳手图标，而非亲自干预工序](/assets/resources/20261027-meta-review-loop/cover-zh.png)

> 系列：Idea-to-Production · 实践篇

"人不在环内"常被误读成"人没工作了"。恰恰相反——这份工作对人的要求**变高了**。本文讲的是这份契约第四条主张如何落地：每周治理报告读什么、元评审怎么做，以及为什么"改进系统"比"审批任务"值钱。

## 为什么值得看

把人类审批全部移除之后，一个尖锐的问题浮出水面：**系统跑偏了怎么办？**

我们的答案不是加一道保险开关，而是换一个介入层级：人不逐任务踩刹车，人每周看仪表、改机器。本文给出这份治理报告的固定结构和一个可复制的元评审动作循环——哪怕你的系统还远未自主，这两个构件现在就能用。同系列前作《人不在环内：一个 AI 自主交付组织的概念契约》给出契约与禁令表，《上线之后，系统如何自己活着》给出系统的循环目录。

## 你将学到三点

1. **治理报告的三章结构值得抄**：效率与稳定性（事实）、迭代节奏（节拍）、质量信号（方差）——三个正交面，缺一面就会盲。
2. **元评审的产出永远是"改系统"而不是"批任务"**：动手的对象是 Agent、技能、工作流、知识这四类资产，不是任何一条具体工单。
3. **升级通道刻意保留但无权**：系统会在越权处通知你，但通知不是请求——学会区分"该知道的"和"该决定的"，是这份工作的核心纪律。

## 每周一 09:00，报告自己长出来

行政与财务角色的治理循环（Job：`admin-report@KylinLab`）每周一 09:00 自动生成公司级周报，落进档案层。结构是写死的三章：

| 章节 | 看什么 | 它回答的问题 |
|---|---|---|
| **效率·成本·稳定性** | 实例在线率、作业运行史（完成/失败/跳过）、任务吞吐、错误率、token 用量与成本 | 机器转得稳不稳、贵不贵？ |
| **迭代节奏** | 各应用 7 天完成量、阶段/类型分布、改进任务频率、L/M 报告是否准点 | 交付的脉搏还规律吗？ |
| **质量信号** | 重试与失败率、升级事件（人工通知记录）、bug 修复数、子代理评审结果 | 方差有没有在变大？ |

三章分别对应事实、节拍、方差，是三个互相正交的观察面——只看一两面，就有方向彻底看不见。

几条硬规定同样值得抄：

- **数据状态先行**。报告开头只允许三种状态：数据在线 / 可达但不可用 / 数据受阻。实测什么写什么，**禁止编造指标**——一份虚构的绿灯周报比没有周报危险一百倍。
- **锁清理不归它**。报告循环被明令禁止碰认领锁表——观察归观察，操作归机件，权限分离写进任务描述里。
- **只写文件，不碰 git**。报告写入档案层目录即完成；提交与归档沿着既定的文档流程走，不让一个"写报告的 Agent"顺手获得提交全库的权力。

## 元评审：读完之后做什么

报告是输入，不是产出。人的每周动作循环长这样：

```text
读治理报告（15 分钟）
  → 挑出一个异常信号（例：某类任务重试率连升三周）
  → 定位到系统资产的四选一：
      Agent 定义 / 技能说明 / 工作流文档 / 领域知识
  → 修改它（这是写作，不是点按钮）
  → 观察后续几周该信号是否回落
```

关键在第四步的"四选一"：**所有问题都要翻译成对四类资产的修改**，因为符号链接绑定全网即时生效（详见《为什么要拆成三个仓库：知识、调度、档案的分离法则》），你改一句工作流，所有实例下一秒就在执行新规则——改进的回路极短，这是自主系统给人的真正红利。

反过来，两类动作被明确禁止：

- **不代批任务**。给某个卡住的任务"放行"，等于在契约上凿洞（《人不在环内》一篇的禁令表）。正确动作是让这类卡住**不再发生**：补文档、加判据、改派发规则。
- **不在报告里加"待我确认"字段**。升级通知通道记录并继续，它不需要回复；一旦你开始回复，第四个主张"人不在环内"就在实践中作废了。

## 通知的素养：该知道的 ≠ 该决定的

三类事件会主动送到你面前：Agent 无权自造的凭证缺失（如某个 API token 过期）、文档化判据裁决不了的歧义（如两个候选回滚版本都不健康）、以及**已自主执行但你必须知道的**生产级动作（如一次已完成的事故回滚）。

读通知的正确姿势是把它当**新闻**而不是**待办**：第三类尤其反直觉——回滚已经执行完、服务已恢复，通知里没有任何问题在等你回答。它的功能只有一个：让你对系统的状态变化永远不感到意外。攒够了这类"新闻"，它们自然会变成下次元评审的选题。

## 为什么这个分工是划算的

拿人类最贵的资源（战略判断）干最杠杆的事（改规则），拿机器最便宜的资源（无限注意力）干最重复的事（执行与汇报）。逐任务审批的世界里，人的带宽是管线的瓶颈；元评审的世界里，**人的判断力是管线的乘数**——每周一次改进，乘以接下来一万条任务。

这也是"gap-free"定义的一部分：当一条完整闭环（想法→发布→报告→新想法）无人值守跑通之后，人的全部工作就只剩这件事——读报告，改机器，再读报告。

## 总结

1. **先给你的系统立一份三章周报**（事实/节奏/方差），哪怕现在靠你手工攒——有了固定的观察面，改进才有固定的靶子。
2. **把每次介入都翻译成对 Agent、技能、工作流、知识四类资产的一次编辑**：审批是消耗，编辑是资产；一周下来你留下的应该是 diff，不是点击。
3. **从下周一开始计时**：读报告 15 分钟，选题 1 个，改资产 1 处，然后在后续周报里盯那个信号——这就是这份工作的全部，也是它值钱的全部。
