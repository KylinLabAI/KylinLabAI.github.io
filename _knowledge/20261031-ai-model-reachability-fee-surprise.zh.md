# 15 个问题欠 0.21 元：AI 平台「先用后付」的隐藏账单

![封面图：深色科技风信息图「0.21 元背后的计费陷阱」，中间是发光的 0.21 元闸门，左右分别是计费时序与失败信号面板，底部提示接新平台前先做五分钟计费体检](/assets/resources/20261031-ai-model-reachability-fee-surprise/cover-zh.jpg)

接任何一家新的 AI 平台，你其实都在不知不觉中回答三个问题：**平台先收费还是先用后收费？想停下来时你握着的是余额还是凭证？额度耗尽时平台会喊还是静默计费？** 这三个答案，决定了你的钱什么时候被花出去、能不能及时停下、以及你的自动化工具能不能提前看见。

这篇文章用一次真实的 0.21 元欠费把三个问题摆上桌面——而它能被发现，靠的既不是监控也不是告警，而是一次操作失误。

## 三个问题：任何 AI 平台的计费体检

### 问题一：先收费，还是先用后收费？

这是**计费时序**。预付模式先充值，余额见底服务就停，意外上限是你已经付的钱；后付模式先调用、平台后记账，等你看到账单钱已经花了。后付的"意外"，上限由平台替你决定。

### 问题二：你的闸门是配额，还是凭证？

这是**成本控制粒度**。有的平台给你配额：设个上限、用完即停，误伤范围只有你自己；有的平台没有配额这东西，想停只能禁用或删除 API Key——而 Key 后面往往挂着所有正在运行的服务。闸门是配额，停下来是"调小一个数字"；闸门是凭证，停下来是"拔管"。

### 问题三：额度耗尽时，平台会喊吗？

这是**失败信号显式度**。会喊的平台明确报错（如 XiaoMi MiMo 的 `Error: Free usage limit`）；不会喊的平台请求照常成功，账在后台记着。

> **自动化只能检测"会喊"的失败。不会喊的失败，输出永远看起来像成功。**

| 维度 | 选项 A | 选项 B | 决定了什么 |
|---|---|---|---|
| 计费时序 | 先付费后使用 | 先使用后收费 | 你多快知道自己在花钱 |
| 成本闸门 | 余额 / 配额 | 凭证（API Key） | 停下来要动什么、误伤多大 |
| 失败信号 | 显式报错 | 静默计费 | 工具能否自动发现 |

## 案例：0.21 元是如何被收走的

我有个小工具：对配置里的每个 `AI Agent × AI Model` 组合发一句"你是什么模型？"判定连通性，既看有没有答案，也看错误信息。对会喊的平台（如 MiMo），工具能识别 `Error: Free usage limit`——模型活着，但你现在不能白用了。

今天这轮全量本身是个失误：我本没打算把所有组合都跑，操作上多走了一步，于是把阿里云百炼等全部配置都问了一遍（`alibaba-cn/glm-5.2`、`alibaba-cn/kimi-k2.7-code`、`alibaba-cn/qwen3.8-*` 等）。全绿，收工。

![连通性测试输出表：ai-agent / ai-model / validate 三列，opencode 与 deepseek agent 下 alibaba-cn 各模型及部分 deepseek 模型每一行均为 VALID](/assets/resources/20261031-ai-model-reachability-fee-surprise/ai-model-reachability.png)

换句话说，这个问题是误操作的副产品——若不是这次多余的全量，它会一直藏着。然后，10:22，短信到了。

![两条阿里云短信：截至 2026-10-29 10:22:01 可用额度 -0.21 元；百炼模型推理服务欠费 0.21 元，累计欠费 0.21 元，已停止服务](/assets/resources/20261031-ai-model-reachability-fee-surprise/aliyun-fee-sms.png)

**百炼模型推理服务欠费 0.21 元，累计欠费 0.21 元，已停止服务。** 注意最后四个字——服务已经被停了，这不是"提醒充值"，而是"你已经不能用了"。

售后答复把机制讲清了：

![阿里云售后答复截图：0.21 元欠费来自 10 月 29 日 10:18–10:20 百炼模型推理调用，涉及 glm-5.2、kimi-k2.7-code 等，免费额度已过期；按量付费为默认计费方式、不支持关闭，止血需禁用或删除所有 API Key](/assets/resources/20261031-ai-model-reachability-fee-surprise/aliyun-feedback.png)

| 事实 | 内容 |
|---|---|
| 欠费来源 | 10 月 29 日 10:18–10:20 的百炼模型推理调用 |
| 涉及模型 | glm-5.2、kimi-k2.7-code 等（免费额度已过期） |
| 计费方式 | 按量付费是默认计费方式，无需单独开通，不支持关闭 |
| 止血办法 | 将所有 API Key 禁用或删除 |

15 次"你是什么模型？"，账单 0.21 元，平均一次约 0.014 元。

**用三问框架复盘这家平台：** 计费时序——默认先使用后收费，无法更改；成本闸门——没有消费上限，唯一闸门是凭证；失败信号——静默计费，额度过期不报错、请求照常成功。

三个答案凑齐，0.21 元的来路就清楚了：**免费额度过期 → 平台不喊 → 工具看到的是成功调用 → 钱在后台记上 → 短信到的时候，服务已经停了。** 同样是没额度，MiMo 明确报错，百炼什么都不提示直接切到按量计费——差别就在这行报错上。

## 三问怎么用：三个可复用做法

### 做法一：新平台注册后做五分钟计费体检

时序上默认预付还是后付、能不能改？闸门上有没有消费上限？额度耗尽会报错还是静默计费？把三个答案写进笔记。"后付 + 无上限 + 静默"三项凑齐，就是收费陷阱的结构，任何自动化调用都该多一层人工确认。

### 做法二：按最小爆炸半径拆分凭证

闸门是凭证的平台，Key 的拆分方式就是风险边界。每个平台单独一个 Key，绝不共用——因为"删 Key"的代价，是 Key 后面所有服务一起停。

### 做法三：把"额度体检"和"连通性测试"分成两份报告

连通性回答"通不通"，额度体检回答"还剩多少、何时到期、现在收不收钱"。对静默计费的平台，额度体检是唯一能提前发现问题的手段。

## 总结与延伸阅读

- 接新平台先做三问体检：先收费还是先用后付？闸门是配额还是凭证？额度耗尽会喊吗？
- 自动化只能检测"会喊"的失败；静默计费的失败输出永远像成功。
- 在后付且无上限的平台上，API Key 是唯一的闸门——按最小爆炸半径拆凭证、把额度体检和连通性测试分开做。

推荐下一步：把"禁用/删除 API Key"写成应急预案并标注误伤范围；给免费额度设到期提醒；跑全量前先估最坏成本。
