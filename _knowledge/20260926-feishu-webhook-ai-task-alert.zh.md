# AI 任务卡住时让飞书来喊你：个人开发者告警最佳实践与 6 种方案对比

![用飞书机器人接收 AI 任务告警：个人开发者零门槛最佳实践](/assets/resources/20260926-feishu-webhook-ai-task-alert/cover-zh.jpg)

你把一个长任务交给 AI 去跑，自己去做别的事。半小时后回来看——任务早在第 2 步就停了：它需要一个只有你才有的凭证、一次网页登录确认，或一个要人拍板的决定。**任务没坏，只是它喊不到你。** 本文给出一个可复用的解法：让 AI 在"需要人工介入"时，主动往你的飞书群发一张卡片，并横向对比国内 6 种方案帮你选型。

## 你将学到三点

1. **选型决策规则**：用"单向 / 双向 × 资质门槛 × 网络要求"三个维度，在 6 种方案里快速锁定适合自己的那一个。
2. **关键取舍**：零门槛的群自定义机器人只能单向；要双向交互就升级到自建应用机器人（长连接版可免公网），代价是个人实名认证并创建个人组织。
3. **告警消息最佳实践**：一条合格的告警 = 标题说清"要你做什么" + 背景说清"卡在哪" + 自带一条可直接复制执行的命令。

## 到底什么时候才需要"人"出场

- 任务缺一个只有你持有的令牌或凭证；
- 某平台网页登录会话过期，无头模式无法自行登录；
- 需确认一次 OAuth 绑定或授权；
- 要执行不可逆操作（建仓库、发版本、花钱）前的拍板；
- 需求有歧义，AI 不敢猜。

共同点是"不紧急到打电话，但拖一小时就白等一小时"。告警通道的核心诉求：即时触达手机、接入成本低、不依赖公网服务器。

## 6 种方案横向对比

| 方案 | 单向 | 双向 | 资质要求 | 免费 | 网络要求 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| 飞书群自定义机器人 | ✅ | ❌ | 普通飞书账号；无需组织、实名或营业执照 | ✅ | 仅单向 |
| 飞书自建应用机器人 | ✅ | ✅ | 个人实名认证；需个人飞书组织 | ✅ | 长连接版免公网（推荐）；Webhook 版需公网 |
| 钉钉群自定义机器人 | ✅ | ❌ | 普通钉钉账号 | ✅ | 仅单向 |
| 钉钉自建应用 | ✅ | ✅ | 个人实名企业 | ✅ | 双向需公网回调 |
| 企业微信自建应用 | ✅ | ✅ | 个人实名企业 | ✅ | 双向需公网回调 |
| 个人微信第三方机器人 | ✅ | ✅ | 个人微信账号 | ✅ | 封号风险高；不推荐 |

**三个维度的读法：**

- **单向 / 双向**：只需要"它喊你"→单向够；想回消息给 AI→双向。
- **资质门槛**：群自定义机器人凭普通账号即可；自建应用普遍要求个人实名（钉钉、企业微信还要求实名企业主体）。
- **网络要求**：没公网服务器时，只有"仅单向"和"长连接版自建应用"两条免公网路径。

## 为什么默认推荐飞书群自定义机器人

普通飞书账号、零实名、零组织、零营业执照；建群 → 加自定义机器人 → 拿 webhook，点几下就好；消息卡片排版强，适合承载"背景 + 行动项"。代价：只能单向，且 webhook 即凭据，泄露可被冒用。

要双向且没公网？升级**飞书自建应用机器人（长连接版）**——唯一"双向 + 免公网"组合。已有企业主体或公网，再考虑钉钉 / 企业微信自建应用；个人微信第三方机器人封号风险高，不推荐。

## 方案总览：它怎么工作

- **AI Agent**：在关键分支判断是否需要人工介入；
- **Webhook**：群自定义机器人的唯一入口，一个 HTTPS POST 地址；
- **消息卡片**：结构化排版，背景与行动项分层；
- **你**：收推送，按卡片命令执行，回填后任务继续。

```text
AI Agent ──POST webhook──▶ 飞书群机器人（单向通知）
      ▲                      │ 卡片推送
      └──── 你执行命令 ────── 飞书 App
```

三条设计不变式：

1. 告警只在真正需要人时发，可自动重试 / 可绕过的不发；
2. 每条告警自带可执行动作，让人 30 秒内能行动；
3. webhook 当密码保管，存环境变量或配置，不进仓库，建议开加签校验。

## 动手配置：也就半小时

- 新建飞书群（只有自己也可），命名"AI 任务告警"；
- 群设置 → 群机器人 → 添加自定义机器人，取有辨识度的名字（如 DevAgent）；
- 复制 webhook 存环境变量或本地配置，不提交仓库；
- 在任务脚本"需人工介入"分支接上 webhook；
- 发一条测试消息验证链路；
- （可选）启用加签校验，防泄露滥用。

发送侧就是一次 HTTPS POST：

```bash
curl -s -X POST "$FEISHU_WEBHOOK" \
  -H "Content-Type: application/json" \
  -d '{
    "msg_type": "interactive",
    "card": {
      "header": { "title": { "tag": "plain_text",
        "content": "Manual action required: <一句话说清要你做什么>" },
        "template": "orange" },
      "elements": [
        { "tag": "div", "text": { "tag": "lark_md",
          "content": "**背景**：<AI 已做到哪一步、卡在哪>\n**Action needed**：\n<可直接复制执行的命令或链接>" } },
        { "tag": "hr" },
        { "tag": "note", "elements": [ { "tag": "plain_text",
          "content": "来自 <Agent 名> · <时间>" } ] }
      ]
    }
  }'
```

## 一条合格告警长什么样

下面是我实际收到的一条：AI 配仓库镜像时，因 Gitee 网页登录会话过期而停，主动在群里喊人。

![飞书群里收到的 AI 任务告警卡片：Manual action required，含背景说明与可直接执行的命令](/assets/resources/20260926-feishu-webhook-ai-task-alert/feishu-notify-message.jpg)

## 推荐矩阵

| 如果你需要…… | 选…… | 因为…… |
|---------------|-------|---------|
| 个人使用、零门槛、今天就要用 | 飞书群自定义机器人 | 无需实名、组织与公网，接入只有一次 HTTPS POST |
| 双向交互且没有公网服务器 | 飞书自建应用（长连接版） | 双向中唯一免公网的选择 |
| 日常已用钉钉，仅单向通知 | 钉钉群自定义机器人 | 同级零门槛，顺手 |
| 有企业主体且需微信触达 | 企业微信自建应用 | 双向完整，微信生态触达好 |
| —— | 避开个人微信第三方机器人 | 封号风险高，不推荐 |

## 总结

我要的到底是"它喊我"，还是"我和它对话"？多数个人开发者只需前者——用最零门槛的飞书群自定义机器人起步即可。今天接上，以后每次 AI 等你，手机都会准时响。
